# 个人理财平台设计规格

日期：2026-09-23  
状态：设计已获用户确认，待规格复核后实施

## 1. 目标与边界

为单一用户部署一个轻量、可自托管的个人理财平台，运行在阿里云 ECS（Ubuntu 24.04，2 vCPU，约 2 GiB RAM）上，通过公网 IP `121.41.225.151` 访问。

平台用于记录资产、分析组合、执行现金流规则和发送提醒，不连接券商或基金账户，不自动下单，不保存交易账户密码。所有买入、卖出和转账动作仍由用户在原有金融机构 App 中确认。

用户当前月度规则：

| 项目 | 金额 | 系统约束 |
| --- | ---: | --- |
| 工资 | 4000 元 | 每月收入记录 |
| 固定支出 | 2700 元 | 计入预算，不可用于投资 |
| 流动储备金 | 1000 元 | 独立现金桶，禁止分配到高波动资产 |
| 投资预算 | 200 元 | 仅从可用投资现金中产生建议 |
| 自由支配 | 100 元 | 不计入投资可用额 |

## 2. 用户体验

### 2.1 访问

- 第一阶段使用 `http://121.41.225.151`。
- 应用进程只监听本机回环地址，由反向代理暴露网页端口。
- 后续如有域名，可无损切换到 HTTPS；没有域名时不强制引入自签名证书。

### 2.2 页面

1. **总览**：总资产、可用现金、流动储备金、投资资产、当月现金流、组合收益和风险提示。
2. **持仓**：基金/资产名称、代码、账户、份额、成本、当前估值、收益率、目标比例、风险标签。
3. **交易记录**：买入、卖出、分红、转入、转出、费用和备注；支持撤销错误录入但不物理删除审计记录。
4. **现金流**：工资、固定支出、储备金、投资预算、自由支配及月度完成度。
5. **组合分析**：核心/卫星分层、资产类别分布、集中度、目标偏离、历史快照和简单曲线。
6. **提醒中心**：每日检查结果、条件触发原因、风险上限、止损纪律和已读状态。
7. **导入与备份**：Excel/CSV 导入、截图数据人工确认、导出 CSV/JSON、备份状态。
8. **设置**：现金流规则、资产分类、通知配置、每日提醒时间和管理员凭据。

### 2.3 本地视觉预览

实现阶段先在本机提供一个仅本机可访问的预览地址（例如 `http://localhost:3000`），用于确认总览布局和移动端体验；预览不访问真实服务器数据。用户确认后再部署到 ECS。

## 3. 技术架构

采用单体、低依赖架构以适配 2 GiB 内存：

- Python 3.12+ 后端，FastAPI 提供页面数据和 JSON API。
- SQLite 作为单用户主数据库，启用 WAL；所有金额以分为单位存储，避免浮点误差。
- 服务端渲染页面加少量原生 JavaScript，减少前端构建和常驻内存。
- systemd 管理应用服务和定时任务，不使用 Docker、1Panel 或 OpenClaw。
- Nginx 作为反向代理，应用仅绑定 `127.0.0.1`。
- 系统日志使用 journald；应用日志按天轮转并限制总容量。

### 3.1 组件

```text
浏览器
  -> 阿里云安全组 TCP 80
  -> Nginx (127.0.0.1:80)
  -> Finance App (127.0.0.1:8000)
  -> SQLite (本地磁盘)
  -> 定时任务：快照、规则检查、通知、备份
```

## 4. 数据模型

- `users`：单一管理员账户、密码哈希、创建时间。
- `accounts`：余额宝、银行卡、基金账户等资金账户。
- `assets`：基金/ETF/现金资产，代码、名称、类别、风险级别、核心或卫星标签。
- `holdings`：账户与资产的当前份额、成本、最新估值及数据更新时间。
- `transactions`：交易类型、金额、份额、价格、费用、发生时间、来源、备注和导入批次。
- `cash_buckets`：固定支出、流动储备金、投资预算、自由支配等现金桶。
- `monthly_budgets`：月份、工资、预算项目、已用金额和结余。
- `allocation_targets`：资产类别/资产的目标比例、上下限和生效日期。
- `price_snapshots`：外部行情或人工录入的价格/净值、来源、时间和可信度。
- `portfolio_snapshots`：每日总资产、现金、各类别估值、收益和数据完整性状态。
- `alerts`：规则、触发值、建议动作、风险说明、状态和通知记录。
- `notification_channels`：邮件 SMTP、微信推送通道的非敏感配置和密钥引用。
- `audit_events`：登录、导入、修改、导出、通知和规则变更记录。

敏感配置（密码哈希、SMTP 授权码、微信 Token、会话密钥）不进入数据库明文和版本库，存放在权限为 `600` 的环境文件中。

## 5. 现金流与投资规则

每月工资入账后，系统按固定顺序建立四个现金桶：2700 元固定支出、1000 元流动储备金、200 元投资预算、100 元自由支配。

- 只有投资预算余额可生成新的投资建议。
- 流动储备金余额低于 1000 元时，默认暂停新增高波动投资，并生成补足提醒。
- 单一卫星资产和全部卫星仓位均有上限；默认值在首次配置时由用户确认，不硬编码为投资建议。
- 组合偏离目标比例时只生成分批调整建议，不自动交易。
- 行情或持仓数据缺失、过期或来源不可靠时，建议状态为“等待数据”，不得推断实时价格。
- 每条建议展示金额/比例、触发条件、最大风险、止损纪律、数据时间和来源。

## 6. 数据输入与行情策略

第一版优先保证数据诚实和可追溯：

- 支持手工录入和 Excel/CSV 导入。
- 支持从用户提供的持仓截图提取候选字段，但必须在导入确认页人工确认。
- 可接入公开基金净值源；每条数据保存来源、抓取时间和失败原因。
- 不宣称实时行情；当日数据不可得时，页面明确显示“缺少数据”，只给条件式建议。
- 每日收盘后生成快照，保留原始导入批次，方便纠错和回溯。

## 7. 提醒设计

### 7.1 邮件

- 邮件作为主通道，使用 SMTP 主机、端口、用户名和授权码。
- 每日摘要包含资产总览、现金桶、数据更新时间、建议动作和风险提示。
- 失败重试有限次数，失败结果写入提醒中心，不循环发送。

### 7.2 微信

支持以下任一适配器，第一版只启用用户选择的一个：

- PushPlus 个人 Token。
- Server酱个人绑定。
- 企业微信机器人 Webhook。

微信通道作为邮件的补充，不作为唯一审计依据。Token 只从受限环境变量读取，页面只显示脱敏状态。

### 7.3 调度

- 默认北京时间每日 09:00 检查数据和规则。
- 每日检查前先验证持仓、现金和行情的新鲜度。
- 用户可在设置中调整时间，但不得绕过缺失数据检查。
- 重大风险提醒立即发送；一般建议合并为每日摘要，避免频繁交易。

## 8. 安全、备份与恢复

- 管理员登录使用 Argon2/bcrypt 密码哈希、会话过期和 CSRF 防护。
- 数据库和环境文件只允许应用用户读取；禁止通过 Nginx 直接下载。
- SSH 继续使用专用密钥，并保持阿里云安全组的来源限制。
- 仅开放网页所需端口；应用端口和 SQLite 不对公网开放。
- 每日 SQLite 在线备份，保留本机轮换副本；结合现有阿里云备份服务做恢复演练。
- 备份文件不包含未加密的 SMTP/微信凭据。
- 不保存基金、银行卡或券商登录密码，不代替用户执行转账和交易。

## 9. 部署与运维

1. 在本地完成页面原型和自动化测试。
2. 创建独立系统用户、虚拟环境、应用目录和受限环境文件。
3. 初始化 SQLite、迁移表结构和默认现金流规则。
4. 配置 systemd、Nginx、日志轮转和备份定时器。
5. 在阿里云安全组放行 TCP 80；SSH 22 仍限制为用户当前公网 IP。
6. 导入现有持仓和交易数据，标记缺失行情，不虚构数值。
7. 用测试通知验证邮件和微信，再启用每日调度。

## 10. 测试与验收标准

- 现金流计算：4000 元工资正确拆分为 2700/1000/200/100。
- 1000 元储备金不足时，新增高波动投资建议自动暂停。
- 交易导入可重复执行，不产生重复持仓或重复现金变动。
- 金额计算无浮点误差，收益和比例在边界值下稳定。
- 缺少或过期行情时不生成伪实时建议。
- 邮件和微信成功、失败、重试状态均可追踪。
- 未登录不能访问管理页面；普通网页端口不能访问数据库和环境文件。
- 服务重启后数据完整；备份可恢复到临时数据库。
- 2 vCPU/2 GiB 环境下页面响应和每日任务在可接受时间内完成。
- 移动端可查看总览、提醒和持仓，并能完成小规模录入。

## 11. 明确不包含的功能

- 自动买入、卖出、申购、赎回或转账。
- 保存基金账户、银行卡、券商或支付平台密码。
- 以实时行情为依据的高频交易。
- 面向多人租户、公开注册和复杂权限系统。
- 在没有可靠数据时给出确定性收益承诺。

## 12. 待用户在实施前确认的配置

- 微信通道：PushPlus、Server酱或企业微信机器人。
- 接收提醒的邮箱和 SMTP 服务商。
- 每日提醒时间（默认北京时间 09:00）。
- 核心/卫星目标比例及单一卫星资产上限。
- 是否先导入当前已有持仓，还是从空账本开始。
