# 基金机会提醒与现金流规则增强设计

日期：2026-09-28  
状态：待用户审阅

## 1. 目标

在现有个人理财平台中增加机会触发式基金建议、可编辑手工净值和可配置提醒调度。系统只在条件满足时推荐未持有或配置不足的基金，不每天轮播候选，也不承诺预测下一日涨跌或自动下单。

本次设计同时明确四个开源项目的使用边界：

- `efinance`：作为 Python 行情数据适配器的参考和可选依赖。
- `xalpha`：作为组合分析、定投、回测和风险指标适配器的参考和可选依赖。
- `funds`：实际为 Vue/Webpack 浏览器扩展，不作为 Python 包导入；只参考实时估值和节假日逻辑。
- `real-time-fund`：实际为 Next.js 应用，不作为 Python 包导入；只参考实时估值和重仓股跟踪逻辑。

## 2. 用户规则

### 2.1 工资周期

每月 15 日为周期起点。一个周期为当月 15 日 00:00 至次月 14 日 23:59，使用 `Asia/Shanghai` 时区计算。

每周期基础现金流：

| 项目 | 金额 | 约束 |
| --- | ---: | --- |
| 工资 | 4000 元 | 周期开始时记录 |
| 固定支出 | 2700 元 | 不得用于投资 |
| 流动储备金目标 | 1000 元 | 正常情况下不得投入高波动资产 |
| 正常投资预算 | 200 元 | 仅从投资预算结余产生建议 |
| 自由支配 | 100 元 | 不计入投资预算 |

### 2.2 储备金补回

特殊机会允许使用最多 100 元储备金，但储备金余额不得低于 900 元。

若上一个工资周期使用了特殊机会储备金，下一周期按以下顺序分配：

1. 先将储备金补回 1000 元；
2. 再恢复完整的 200 元正常投资预算；
3. 不得挪用固定支出或自由支配金额补足投资预算。

在储备金尚未补回 1000 元之前，本周期不生成特殊机会买入建议，也不恢复完整的 200 元正常投资预算。补足储备金后，剩余可用资金才可以恢复正常投资预算；特殊机会追加额度仍为本周期最多 100 元且最多触发一次。

### 2.3 特殊机会

每个工资周期最多触发一次特殊机会追加预算，追加上限为 100 元。正常投资预算 200 元优先使用，特殊机会资金只能在明确满足机会条件时使用。

## 3. 建议行为

系统输出以下一种主动作：

- `BUY`：买入；
- `BUY_IN_BATCHES`：分批买入；
- `HOLD`：持有；
- `REDUCE_IN_BATCHES`：分批减仓；
- `SELL`：卖出；
- `WAIT`：不操作；
- `WAIT_FOR_DATA`：等待数据；
- `WATCH`：加入观察名单。

### 3.1 普通建议

普通建议在用户设定的每日提醒时间汇总发送。默认时间为北京时间 14:00。没有满足条件的候选时不发送基金候选名单，只在平台内记录“不操作”或“等待数据”。

### 3.2 特殊机会建议

特殊机会不等待下一次日常汇总。只有以下条件全部满足才允许触发：

- 当前组合存在明确的核心或卫星配置缺口；
- 候选基金与已有持仓重复度不高；
- 风险等级在用户允许范围内；
- 当前估值不处于明显历史高位；
- 近期不存在异常快速上涨导致的追高风险；
- 数据来源可靠、更新时间满足新鲜度要求；
- 当前工资周期已完成储备金补足，且仍有正常投资预算，或本周期尚未使用过特殊机会预算；
- 触发后储备金余额不低于 900 元。

特殊机会提醒包含基金代码、建议金额、资金来源、触发原因、最大风险和后续纪律。系统只发送提醒，不调用基金交易接口，不自动提交订单。

## 4. 行情与分析架构

### 4.1 适配器边界

后端新增统一的行情接口，适配器返回统一数据结构：

- 基金代码和名称；
- 正式净值或实时估算值；
- 估值日期和抓取时间；
- 数据类型：`OFFICIAL_NAV` 或 `INTRADAY_ESTIMATE`；
- 数据来源；
- 原始响应摘要；
- 错误原因和重试状态。

`efinance` 适配器优先用于基金历史净值、最新净值和盘中估算。`xalpha` 适配器用于定投、组合收益、回撤、波动率、目标偏离和回测计算。

### 4.2 第三方项目边界

`funds` 是浏览器扩展，`real-time-fund` 是 Next.js 应用，当前项目不把它们当作 Python 依赖安装，也不在 2 vCPU/2 GiB 服务器上额外常驻 Node 服务。仅参考其公开功能和数据处理思路，在本项目中实现独立的交易日历、估算净值展示和重仓跟踪能力。

项目不得复制 GPL-3.0 或 AGPL-3.0 项目的源码到当前公共仓库。若未来需要运行其原项目，必须单独部署并保留其许可证和源代码义务。

### 4.3 正式净值与估算净值

- 正式净值用于持仓估值、组合快照和正式规则判断；
- 实时估算仅用于盘中参考和机会筛选；
- 页面和提醒必须显示数据类型、来源和时间；
- 估算净值不得覆盖正式净值；
- 估算数据缺失或过期时不得推导确定性买卖结论。

## 5. 机会筛选与防追高

候选基金必须经过以下检查：

1. 组合缺口：目标比例和当前比例存在可配置的偏离；
2. 重复度：与现有资产的行业、指数或风格暴露不超过配置上限；
3. 估值位置：不处于历史高位区间；
4. 动量限制：近期连续快速上涨时降级为 `WATCH`；
5. 回撤限制：下跌过快且没有稳定信号时降级为 `WATCH`；
6. 成本和质量：检查费用、规模、历史长度、基金经理信息和跟踪误差；
7. 现金约束：根据当前周期剩余预算计算建议金额。

系统不输出“明天必涨”或概率承诺。建议文本必须包含：

> 本建议基于已确认行情、历史统计和资产配置规则生成，仅供辅助决策，不构成涨跌预测，也不保证收益。

## 6. 提醒调度

- 默认 `daily_schedule=14:00`，时区为 `Asia/Shanghai`；
- 设置页面允许修改为合法的 `HH:MM`；
- systemd timer 继续每 5 分钟唤醒，由应用判断是否到达时间窗口；
- 周六、周日始终返回 `NOT_DUE`；
- 配置中的中国法定节假日返回 `NOT_DUE`；
- 调休周末仍按用户规则跳过；
- 特殊机会不受日常汇总时间限制，但仍需通过节假日和数据新鲜度检查；
- 同一机会在同一周期只发送一次，避免重复提醒。

节假日数据采用可维护的本地配置，记录节日名称、日期和来源。配置缺失时默认只执行周末跳过，并在设置页标记日历需要更新，不将工作日误判为节假日。

## 7. 手工净值编辑

当前同一资产、估值日期和来源的价格冲突会报错。本次改为：

- `/prices` 显示最近手工净值记录；
- 新增 `/prices/{id}/edit` 页面；
- 新增 `/prices/{id}` 更新提交；
- 允许修改价格、估值日期和来源；
- 保存旧值、新值、操作者和时间；
- 写入 `price.updated` 审计事件；
- 外部正式数据不能从手工编辑页直接覆盖；
- 价格必须为正数，日期和来源必须通过现有表单校验。

## 8. 数据流与失败处理

```text
行情适配器
  -> 统一行情记录
  -> 正式净值/估算净值分类
  -> 组合与现金流规则
  -> 普通提醒或特殊机会提醒
  -> 邮件通知与提醒中心审计
```

失败处理规则：

- 单一数据源失败时记录失败原因并尝试备用来源；
- 所有来源失败时返回 `WAIT_FOR_DATA`；
- 不用旧估值冒充当日数据；
- 估算和正式净值不一致时保留两者并提示差异；
- 通知失败有限次数重试，最终写入提醒中心；
- 任何建议都记录输入数据时间、来源、规则版本和资金周期。

## 9. 页面变更

设置页面新增或调整：

- 工资日，默认 15 日；
- 每日提醒时间，默认 14:00；
- 法定节假日配置状态；
- 正常投资预算和特殊机会上限；
- 储备金目标和最低余额；
- 核心/卫星目标比例和单项上限。

提醒中心新增：

- 建议动作和资金来源；
- 触发条件；
- 数据类型、来源和时间；
- 是否已使用本周期特殊机会预算；
- 风险和纪律说明。

## 10. 测试与验收

必须覆盖：

- 15 日至次月 14 日的周期边界；
- 工资 4000 元拆分为 2700/1000/200/100；
- 储备金从 900 元补回 1000 元后才恢复投资预算；
- 特殊机会每周期最多一次且最多 100 元；
- 特殊机会不会让储备金低于 900 元；
- 默认提醒时间为 14:00，用户设置可以覆盖；
- 周末和法定节假日不提醒；
- 同一机会同一周期不重复发送；
- 手工净值可以修改并生成审计事件；
- 正式净值和估算净值分开保存；
- 数据不足时不生成买入或卖出动作；
- 估值处于高位或短期暴涨时不会触发买入；
- `efinance`/`xalpha` 适配器失败时系统仍能降级为手工数据模式。

## 11. 不包含的功能

- 自动提交基金申购、赎回或股票交易订单；
- 保证下一日涨跌预测准确；
- 使用储备金超过 100 元；
- 同一工资周期多次触发特殊机会；
- 在缺少可靠数据时猜测行情；
- 直接复制 GPL-3.0 或 AGPL-3.0 项目源码到当前仓库。
